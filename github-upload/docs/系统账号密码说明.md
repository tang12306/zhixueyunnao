## 权限说明

| 角色 | 前端登录 | 管理接口 | 修改系统设置 |
| --- | --- | --- | --- |
| ADMIN | ✅ | ✅ | ✅ |
| TEACHER | ✅ | ✅ | ❌（只读） |
| STUDENT | ❌ 学生端暂未开放 | ❌（403） | ❌ |
| 未登录 | — | ❌（401） | ❌ |

- 除登录接口外，所有 `/api` 接口都需要登录。
- 连续 5 次密码错误后，该账号在同一 IP 上锁定 15 分钟（返回 429）。
- AI 生成接口每个用户每分钟最多 5 次（`AI_RATE_LIMIT_PER_MINUTE` 可调整）。
- 修改密码时新密码至少 8 位。

## 数据库连接信息

### MySQL数据库
- **主机**：127.0.0.1（容器端口只对本机开放）
- **端口**：3306
- **数据库名**：education_question_bank
- **用户名**：`DB_USERNAME`（默认 `root`）
- **密码**：`.env` 中的 `DB_PASSWORD`，使用 `mysql -p` 交互输入，不在命令行或仓库中保存

### 数据库查询命令
```bash
# 查看教师和管理员账号
mysql -u root -p -h 127.0.0.1 -P 3306 education_question_bank -e "SELECT username, name, role FROM users WHERE role IN ('TEACHER', 'ADMIN');"

# 查看学生账号（前5个）
mysql -u root -p -h 127.0.0.1 -P 3306 education_question_bank -e "SELECT username, name, role FROM users WHERE role = 'STUDENT' LIMIT 5;"
```

## API测试

登录使用会话 Cookie（JSESSIONID，HttpOnly），不再返回 token。写操作（POST/PUT/DELETE）需要带上 `XSRF-TOKEN` Cookie 的值作为 `X-XSRF-TOKEN` 请求头，前端 axios 会自动处理。

### 测试登录接口
```bash
curl -c cookies.txt -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "username": "demo.teacher",
    "password": "DemoTeacher123!"
  }'

# 带着会话查询当前用户
curl -b cookies.txt http://localhost:8080/api/auth/me
```

### 预期响应
```json
{
  "success": true,
  "message": "登录成功",
  "user": {
    "id": 1,
    "username": "demo.teacher",
    "name": "演示教师",
    "email": null,
    "role": "TEACHER"
  }
}
```

### 常见错误响应

| 状态码 | message | 原因 |
| --- | --- | --- |
| 400 | 请输入用户名和密码 | 用户名或密码为空 |
| 401 | 用户名或密码错误 | 账号不存在或密码错误 |
| 403 | 学生端暂未开放，请使用教师或管理员账号登录 | 学生账号 |
| 429 | 登录失败次数过多，请 N 分钟后再试 | 连续失败被锁定 |

## 登录问题排查

1. **前后端是否在运行**
   ```bash
   netstat -ano | findstr :8083
   netstat -ano | findstr :8080
   ```
2. **没有任何账号能登录**：生产配置下需要在 `.env` 设置 `APP_ADMIN_USERNAME` / `APP_ADMIN_PASSWORD` 后重启后端；本地开发可以设 `SPRING_PROFILES_ACTIVE=dev` 使用演示账号。
3. **提示“页面已过期，请刷新后重试”**：CSRF 令牌过期，刷新页面即可。
4. **“Loading chunk failed”**：按 Ctrl+F5 强制刷新；仍然出现时删除 `frontend/node_modules/.cache` 后重启前端。

## 密码加密说明

- 系统使用 BCrypt 加密存储密码，数据库中只保存哈希值
- 接口响应中不会返回密码字段

## 安全注意事项

1. **生产环境部署时**：
   - 不要设置 `SPRING_PROFILES_ACTIVE=dev`
   - 首次登录后修改管理员初始密码
   - 配置 HTTPS，并设置 `COOKIE_SECURE=true`
   - 限制数据库访问权限

2. **开发环境**：
   - 演示密码公开在仓库中，只能用于本地测试
