# 🚀 启动脚本使用说明 v3.0

> v3.0 起 Node.js 后端和 MongoDB 已下线，脚本只启动 MySQL、Spring Boot 和 Vue 前端。

## 📁 脚本文件说明

#### 1. `start-simple.bat` - 启动脚本 ⭐
- **功能**: 启动整个系统
- **使用**: 双击运行即可。首次运行如果没有 `.env`，会从 `.env.example` 复制一份后退出，填好 `DB_PASSWORD` 再运行一次。

#### 2. `stop.bat` - 停止脚本
- **功能**: 关闭启动脚本打开的服务窗口，执行 `docker compose down`，并检查 8080/8083 端口是否已释放
- **使用**: 双击运行即可

## 🔧 启动流程

1. **环境检查**: 检查 Java 和 Docker 是否可用；检查 `.env` 是否存在
2. **清理旧窗口**: 只关闭标题为 “Spring Boot Backend” 和 “Vue.js Frontend” 的窗口，不会结束其他 Java/Node 进程
3. **启动 MySQL**: `docker compose up -d`（端口 3306，只监听本机）
4. **等待 MySQL 就绪**
5. **启动 Spring Boot 后端**（端口 8080）: 优先使用 `mvnw.cmd`，没有时使用系统 `mvn`
6. **启动 Vue 前端**（端口 8083）: `npm run serve`
7. **等待服务启动**（约 60-90 秒），然后打开浏览器

## ⚙️ `.env` 配置

| 变量 | 说明 |
| --- | --- |
| `DB_PASSWORD` | 必填，MySQL root 密码 |
| `DEEPSEEK_API_KEY` | 使用 AI 功能时填写 |
| `APP_ADMIN_USERNAME` / `APP_ADMIN_PASSWORD` | 数据库里没有管理员时创建首个管理员（密码至少 8 位） |
| `SPRING_PROFILES_ACTIVE` | 本地开发填 `dev`（创建演示账号）；生产环境留空 |

## ⚠️ 常见问题与解决方案

### 1. 端口被占用
**解决方案**: 先运行 `stop.bat`；仍被占用时用 `netstat -ano | findstr :8080` 找到进程后手动结束

### 2. Java 环境问题
**解决方案**:
- 确保已安装 Java 17 或更高版本
- 检查 JAVA_HOME 环境变量
- 重启命令提示符

### 3. MySQL 启动失败
**解决方案**:
- 确保 Docker Desktop 正在运行
- 确认 `.env` 里填写了 `DB_PASSWORD`

### 4. 后端报 “Access denied for user 'root'”
**原因**: 数据库卷是用另一个密码创建的，修改 `.env` 不会改变已有数据库的密码
**解决方案**: 在 `DB_PASSWORD` 填写原来的密码；或执行 `docker compose down -v` 重建（会删除所有数据）

### 5. 登录提示 “学生端暂未开放”
学生端尚未开发，前端只接受教师和管理员账号登录。

## 📋 系统要求

- ✅ **Java 17+**: Spring Boot 运行环境
- ✅ **Node.js 18+**: 前端运行环境
- ✅ **Docker Desktop**: 数据库容器
- **Maven**: 可选，仓库自带 Maven Wrapper
- **操作系统**: Windows 10/11（其他系统请参考 README 中的手动命令）

## 🎯 端口使用说明

- **8080**: Spring Boot 后端 API 和旧版页面
- **8083**: Vue.js 前端界面
- **3306**: MySQL 数据库（只监听 127.0.0.1）

## 📞 故障排除

### 日志查看
- **Spring Boot**: 查看 “Spring Boot Backend” 窗口
- **Vue.js**: 查看 “Vue.js Frontend” 窗口
- **MySQL**: 运行 `docker compose logs mysql`

### 常用命令
```bash
# 查看端口占用
netstat -ano | findstr :8080

# 查看 Docker 容器状态
docker ps

# 重启数据库容器
docker compose down
docker compose up -d
```
